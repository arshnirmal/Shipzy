# Database Migration Guide

## Overview

We use **Drizzle ORM** with **Drizzle Kit** to generate SQL migrations from TypeScript schema definitions. This ensures a **single source of truth** - the TypeScript schema files in `schema/`.

## Folder Structure

```
database/
├── schema/          # TypeScript schema definitions (SINGLE SOURCE OF TRUTH)
├── migrations/      # Generated SQL migrations (auto-generated, git-tracked)
├── setup.sql        # Extensions & schema creation (manual, one-time setup)
├── functions/       # Stored functions (PL/pgSQL)
└── queries/         # Raw SQL queries
```

## Workflow

### 1. Make Schema Changes

Edit TypeScript schema files in `schema/`:
- `schema/users.ts`
- `schema/orders.ts`
- `schema/logistics.ts`
- etc.

### 2. Generate Migration

```bash
npm run db:generate
```

This will:
- Compare your TypeScript schema with the database
- Generate SQL migration files in `migrations/`
- Create files like `0000_initial.sql`, `0001_add_column.sql`, etc.

### 3. Review Generated SQL

Check the generated migration files in `src/database/migrations/`:
- Review the SQL for correctness
- Ensure indexes, constraints, etc. are correct
- Modify if needed (but prefer fixing the TypeScript schema and regenerating)

### 4. Deploy Migration

```bash
npm run db:deploy
```

This will:
- Run `setup.sql` (extensions & schemas) if not already run
- Execute pending migrations in order
- Track executed migrations in `_deployment_log` table
- Update stored functions

## Initial Setup

For a fresh database:

1. **Run setup** (extensions & schemas):
   ```bash
   psql -f src/database/setup.sql
   ```

2. **Generate initial migration**:
   ```bash
   npm run db:generate
   ```

3. **Deploy**:
   ```bash
   npm run db:deploy
   ```

## Best Practices

### ✅ DO:
- **Always edit TypeScript schema** (`schema/*.ts`) - this is the source of truth
- **Generate migrations** after schema changes
- **Review generated SQL** before deploying
- **Commit migrations** to git (they're part of the codebase)
- **Test migrations** on a dev database first

### ❌ DON'T:
- **Don't edit SQL migrations directly** - fix the TypeScript schema instead
- **Don't delete old migrations** - they're needed for database history
- **Don't edit `setup.sql`** after initial deployment (unless adding new extensions)

## Migration Files

### Generated Migrations (`migrations/*.sql`)
- Auto-generated by Drizzle Kit
- Named with timestamps: `0000_initial.sql`, `0001_add_column.sql`
- Contains `CREATE TABLE`, `ALTER TABLE`, etc.
- **Git-tracked** - commit these files

### Setup SQL (`setup.sql`)
- Manual file for extensions and schema creation
- Run once per database
- Contains `CREATE EXTENSION`, `CREATE SCHEMA`
- **Git-tracked** - version controlled

### Stored Functions (`functions/*.sql`)
- Manual PL/pgSQL functions
- Always re-run on deployment (uses `CREATE OR REPLACE`)
- **Git-tracked** - version controlled

## Troubleshooting

### Migration conflicts
If migrations are out of sync:
1. Check `_deployment_log` table
2. Manually fix database state if needed
3. Regenerate migrations: `npm run db:generate`

### Schema drift
If database doesn't match schema:
1. Generate migration: `npm run db:generate`
2. Review the diff
3. Deploy: `npm run db:deploy`

### Need to reset
For development only:
```bash
# Drop and recreate database
dropdb shipzy_dev
createdb shipzy_dev

# Run setup
psql -d shipzy_dev -f src/database/setup.sql

# Deploy all migrations
npm run db:deploy
```

## Migration Commands

| Command | Description |
|---------|-------------|
| `npm run db:generate` | Generate SQL migrations from TypeScript schema |
| `npm run db:deploy` | Deploy pending migrations to database |

## Files to Keep

- ✅ `schema/*.ts` - TypeScript definitions (source of truth)
- ✅ `migrations/*.sql` - Generated migrations (git-tracked)
- ✅ `setup.sql` - Extensions & schemas (git-tracked)
- ✅ `functions/*.sql` - Stored functions (git-tracked)

## Files to Remove

- ❌ `schemas/*.sql` - **DEPRECATED** - Use Drizzle migrations instead
